# RT编码器只读观测

用于本台类型12编码器的机械位置核实；同时允许相同原工程协议的类型13。其他类型保持未初始化且valid=0。
原工程SV_RtT036.c与对照工程完全一致：读取命令0x6A、返回11字节，前10字节异或校验第11字节。
本实现复用UART引脚和2.5 Mbaud设置；硬件版本1使用UART2时按UART2时钟计算波特率。
每1ms非阻塞接收上次响应并发下一条0x6A，只读位置，不调用含校准/清零的RT_Process。
不写编码器参数，不调用旧外环或Etheta.calc，不改变FOC控制角度。原电流环、启动保护和邮箱ABI保持原样。

## 数据入口
J-Link/GDB使用同次发布ELF：`p g_sl_encoder`。独立ABI=2，目标结构8356字节；旧ABI1的148字节导出器不能解码本版完整轨迹。
运行时必须使用无暂停读取；sequence读取前后相同且为偶数时才采用整块快照。
新固件会改变RAM地址，不得沿用上一版硬编码地址。

- initialized：已执行支持类型的UART初始化，不等于通信成功。
- good_frames/requests：有效响应与请求计数，停机时仍应持续增长。
- valid：最新一次响应长度、校验、状态、位置范围均通过；静止也可有效，不以位置变化判新鲜。
- reason：0有效、1未初始化/不支持、2长度/缺帧、3CRC、4编码器状态非零、5位置范围错误。
- status/header：最近收到的完整帧原始字段。状态非零按保守策略判无效，具体位义尚未独立核对。
- motor_raw/output_raw：电机端/输出端原始单圈值，不叠加方向或零偏。坏帧后保留旧值，但valid立即为0。
- tick_ms/last_good_ms/age_ms：服务计数与最新好帧时间；读数时还需观察tick与good_frames是否持续增长。
- record_id：每次实际驱动使能上升沿开始新记录。before_*保存前一帧位置，after_*保存下降沿采样。
- before_valid/after_valid/run_valid：起点、终点、全程有效性；任一运行坏帧使run_valid锁存为0，后续好帧不掩盖。
- motor_delta/output_delta及min/max：相对起点的最短回绕位移，只有before_valid和run_valid均为1才作机械对比。
- run_samples/run_errors：使能期间及下降沿的接收次数/坏帧次数。停机后结果保留，下一次使能才替换。

按原工程解码约定，电机端一圈131072计数、输出端一圈524288计数；角度=count*360/一圈计数。
这两个分辨率来源于原工程，不代表已经通过实物规格校准。位置差算法仅用于小范围定位，不适合累计多圈运动。
采样时间分辨率约1ms，前一帧作为起点；末端下降沿捕获不等于机械完全停稳，可另读停机后的live位置。

## 更新后的操作
1. 更新本版BANK0后重新上电，保持Servo OFF，不写PE-20=4。
2. 核实Flash/ELF身份，从匹配ELF重新提取地址。只读观察至少两次good_frames、valid、reason、原始位置。
3. 没有连续有效帧时先诊断UART/接线/协议，不重复电机定位。
4. 有效帧稳定后，应用并读回同一低电流限时ALIGN参数；动作前后导出g_sl_encoder及原电流记录。
5. 结合电机端和输出端位移判断是否真实运动。若run_valid=0，不能把零位移当作未动。

生产邮箱与原trace结构未变化；其中encoder_valid仍为0。本版独立诊断原始位置尚未接成速度/电角度反馈。
诊断结构RAM为8356字节，比ABI1增加8208字节，另有2字节内部请求状态（对齐以MAP为准）。不在PWM ISR新增串口处理；1ms服务最多读11字节，无阻塞打印或等待。
实板UART响应、1ms ISR耗时、位置分辨率仍需上机核实。软件测试不能替代这些验证。
